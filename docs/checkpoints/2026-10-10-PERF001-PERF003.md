# TubeBender PERF-001 + PERF-003 engineering checkpoint — 2026-10-10

## Authoritative requirement wording
- **PERF-001:** Ordinary edits of one parameter must visibly update the model without noticeable delay on a representative project.
- **PERF-003:** Failure of one optional module must not cancel `bind()` or disable the whole tool palette.

## Changes in feature/perf-001-003-render-startup-20261010
1. `src/domain/performance/render-startup.mjs`: a single-flight animation frame coalescer with latest-state semantics, plus fault-isolated startup stages.
2. `scripts/build-standalone.mjs`: move costly 3D `renderViewerOnly` from every synchronous `renderAll` call to next animation frame. This preserves synchronous editing of model data and drawing of textual controls while coalescing repeated viewport rebuilds.
3. Avoid double project collision-analysis calculation in a single `renderAll` pass; `renderBoundsWarning` already computes and stores the analysis.
4. Startup phases `ensureIndustrialState`, `ensureCurrentTubeVisible`, `bind`, and `renderAll` execute in separate error boundaries; costly initial redraw is deferred to the next frame.
5. Individual optional UI picker initializers have their own error boundaries; missing optional DOM nodes do not prevent binding later controls.
6. `window.TubeBenderRenderPerformance` provides `pending` and `stats` for diagnostics. `window.TubeBenderStartupStatus` exposes the completed/failed startup phases.

## Automated tests
- `tests/core/perf-001-003.test.mjs`: 50 rapid edits collapse into one frame; latest edit wins; cancellation/stale-draw protection; exception recovery; failures before and within reporting do not prevent `bind`.
- `tests/browser/perf-001-003.spec.mjs`: verifies startup binding and coalesced redraw in real Chromium.
- `.github/workflows/perf-001-003.yml`: Node tests, fresh standalone build, generated contract assertions, browser run, trace artifact.
- GitHub Actions `core-perf` at run #38053023297: PASSED. Chromium job under verification at checkpoint creation.

## Acceptance boundary
This engineering change *implements* deferred/coalesced rendering and fault-isolated startup, but **does not yet prove** the qualitative `PERF-001` target of imperceptible delay for a representative CAD project. That requires measured interaction-to-paint latency on reference projects; if Chromium is unresponsive, do not mark PERF-001 fully accepted.
PERF-003 unit failure-injection passes, but browser resilience still requires the Playwright scenario and preferably a real failed optional module.
