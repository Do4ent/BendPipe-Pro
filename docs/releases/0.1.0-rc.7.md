# BendPipe-Pro 0.1.0-rc.7

Fix the base/classic-looking interface appearing during initial load or page refresh. Previously CAD Workspace was mounted only on window `load`; delayed resources could leave the shared base shell visible. CAD now mounts at DOMContentLoaded after the shared shell, and reference controls start on the explicit CAD-ready event. Before readiness, the page shows a loading status; failed initialization reports an error without exposing the base interface.

Browser regressions deliberately hold both DOM readiness and the load event. They verify that no base interface is visible during startup, CAD works before optional resource completion, refresh restores compact-icon preferences, and finishing load does not duplicate the ribbon or Properties editor. Application shortcuts are blocked during loading or a startup failure, while browser reload remains available; a failure test verifies that Enter/Space cannot repeat a hidden model command. Existing Node, full Chromium, DWFx round-trip, persistence and WebGL gates also apply.

The single HTML, native editors, four toolbar modes and layer commands from rc.6 remain. Project schema, canonical geometry, source evidence, confidence and machine compensation are unchanged.

Download the ZIP, extract it and open **BendPipe_Pro_CAD_Workspace.html** in Chromium. This is an evaluation release candidate. The recognition/manufacturing limits from rc.4 still apply: 80005311 and 80005313 retain blocked whole-project imports, and unresolved geometry, material, tooling and machine settings retain manufacturing blockers. Save project JSON before moving between browser origins or HTML files.
